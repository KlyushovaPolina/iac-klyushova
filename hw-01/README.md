# HW-01 — автоматизированный стенд в Yandex Cloud

## Назначение

В каталоге находится набор Bash-сценариев для автоматизированного создания, проверки и удаления стенда в Yandex Cloud.

Стенд состоит из:

- двух веб-серверов, размещённых в зонах `ru-central1-a` и `ru-central1-b`;
- приватного сервера приложения без публичного IP-адреса;
- виртуальной сети и двух подсетей;
- NAT-шлюза и таблицы маршрутизации;
- целевой группы веб-серверов;
- сетевого балансировщика.

Веб-серверы обслуживают запросы через балансировщик. Сервер приложения доступен веб-серверам по внутреннему адресу, а исходящий доступ в интернет осуществляется через NAT-шлюз.

## Состав сценариев

| Файл | Назначение |
|---|---|
| `create.sh` | создаёт стенд |
| `check.sh` | проверяет состояние стенда |
| `destroy.sh` | удаляет созданную инфраструктуру |

Сценарий `create.sh` является идемпотентным: при повторном запуске существующие ресурсы обнаруживаются и повторно не создаются.

## Запуск стенда

Перед запуском необходимо установить и настроить:

- Yandex Cloud CLI (`yc`);
- `jq`;
- Bash.

Также CLI должен быть авторизован и настроен на нужное облако, каталог и зону.

Перейдите в каталог со скриптами:

```bash
cd hw-01
```

Для создания стенда с параметрами по умолчанию (2 веб-сервера) выполните:

```bash
./create.sh
```

Повторный запуск `create.sh` на уже существующем стенде не должен создавать дубликаты ресурсов.

Количество веб-серверов можно изменить с помощью параметра:

```bash
./create.sh --vm-count 3
```

`--vm-count` должен содержать положительное целое число.

Количество машин также можно задать через переменную окружения:

```bash
VM_COUNT=3 ./create.sh
```

При одновременном использовании переменной окружения и аргумента командной строки аргумент имеет более высокий приоритет:

```bash
VM_COUNT=3 ./create.sh --vm-count 2
```

В этом случае будет использовано значение `2`.

## Проверка стенда

После создания инфраструктуры выполните:

```bash
./check.sh
```

Сценарий выполняет три проверки:

1. балансировщик отвечает по HTTP кодом `200`;
2. запросы распределяются между несколькими веб-серверами;
3. сервер приложения доступен с веб-сервера по внутреннему адресу.

Если все проверки успешны, `check.sh` завершается с кодом `0`.

Если хотя бы одна проверка завершилась ошибкой, возвращается код `1`.

Проверить код завершения можно командой:

```bash
echo $?
```

## Если `check.sh` вернул ошибку

Сначала определите, какая именно проверка завершилась ошибкой. Сценарий выводит результат каждой проверки отдельно.

### Ошибка проверки балансировщика

Если появляется сообщение:

```text
✗ балансировщик отвечает: ...
```

необходимо проверить состояние балансировщика и виртуальных машин:

```bash
yc load-balancer network-load-balancer list
yc compute instance list
```

Убедитесь, что балансировщик существует, а веб-серверы находятся в рабочем состоянии.

### Ошибка распределения запросов

Если появляется:

```text
✗ распределение не работает: ответила одна машина
```

это означает, что ответы в ходе десяти запросов были получены только от одного веб-сервера.

Проверьте состояние обеих машин:

```bash
yc compute instance list
```

Также можно проверить работу nginx на соответствующих веб-серверах.

### Ошибка доступа к серверу приложения

Если появляется:

```text
✗ сервер приложения недоступен с ...
```

необходимо проверить, что приватный сервер существует и доступен по внутреннему адресу.

Проверьте список виртуальных машин:

```bash
yc compute instance list
```

Сервер приложения не должен иметь публичного IP-адреса. Проверка его доступности выполняется с веб-сервера по внутреннему адресу.

Если проблема возникла после изменения сетевой конфигурации, необходимо проверить подсеть сервера приложения, таблицу маршрутизации и NAT-шлюз.

## Удаление стенда

Для полного удаления созданной инфраструктуры выполните:

```bash
./destroy.sh
```

Сценарий удаляет ресурсы стенда с учётом зависимостей между ними.
